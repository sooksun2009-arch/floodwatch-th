# FloodWatch TH — เช็คน้ำท่วมก่อนออกรถ

แอปตอบคำถามเดียว: **"จะไปจาก A ไป B ตอนนี้ มีน้ำท่วมไหม"**

ตอบด้วยหลักฐาน 3 ชั้น เรียงตามความน่าเชื่อถือ:

1. **กล้อง CCTV ตามเส้นทาง** — เรียงตามกิโลเมตรของเส้นทาง เปิดดูภาพจริงก่อนออกรถ
2. **รายงานจากผู้ใช้และหน่วยงาน** — ประมวลเป็นคำตัดสิน ไปได้ / ระวัง / เสี่ยง / ไม่ควรไป
3. **แชทบอทภาษาไทย** — ถามเป็นภาษาพูด เช่น "จากบางนาไปรามคำแหง ท่วมไหม"

เสริมด้วย **สถานีวัดระดับน้ำ 805 สถานีทั่วประเทศ** จากคลังข้อมูลน้ำแห่งชาติ
อัปเดตทุก ~10 นาที เป็นข้อมูลจากเครื่องมือวัด ไม่ใช่ความเห็นของคน
และเป็นสัญญาณเตือนล่วงหน้าว่าย่านไหนกำลังจะมีปัญหา

## สถานะ

ผ่านการทดสอบอัตโนมัติ **183 รายการ** ครอบคลุม API, เครื่องคำนวณเส้นทาง, แชทบอท,
ตัวนำเข้าข้อมูล การหลบจุดน้ำท่วม สถานีวัดระดับน้ำ และการอัปเดตโครงสร้างฐานข้อมูล

```
backend/smoke_test.py     32 checks — auth, reports, moderation, voting, cameras, stats
backend/test_routing.py   45 checks — geometry, Thai route parsing, chatbot intents
backend/test_import.py    40 checks — coordinate/depth parsing, CSV/paste import
backend/test_avoid.py     10 checks — flood-avoidance polygons, graceful fallback
backend/test_stations.py  39 checks — gauge parsing, bad upstream data, station API
backend/test_migrate.py   10 checks — additive schema sync on an existing database
frontend/smoke.cjs         7 checks — loads the app in a real browser, map drew pins
```

`smoke.cjs` is not optional polish. The backend suite passed 176 checks while the
map rendered **zero pins** in both dev and production, because maplibre's Web
Worker 404'd: the API was fine, the basemap drew, and nothing said a word. Only
a real browser sees that class of failure.

## รันในเครื่อง

ต้องมี Python 3.12+ และ Node 20+

```bash
# Backend
cd backend
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt   # Windows
# source .venv/bin/activate && pip install -r requirements.txt   # macOS/Linux
.venv/Scripts/python -m uvicorn app.main:app --reload --port 8000

# Frontend (อีกหน้าต่างหนึ่ง)
cd frontend
npm install
npm run dev          # http://localhost:5173
```

ครั้งแรกระบบจะสร้าง 77 จังหวัด, 50 เขตกรุงเทพฯ, บัญชี `admin` / `admin1234`
และข้อมูลสาธิตให้อัตโนมัติ

รันชุดทดสอบ:

```bash
cd backend
for t in smoke_test test_routing test_import test_avoid test_stations test_migrate; do
  .venv/Scripts/python $t.py
done

# ต้องรันคู่กันเสมอ — ฝั่ง backend มองไม่เห็นว่าแผนที่วาดอะไรหรือไม่
cd ../frontend && npm run smoke            # ทดสอบ dev server ที่ :5173
npm run build && npm run smoke http://localhost:8000/   # ทดสอบ production build
```

`npm run smoke` ต้องมี Chrome หรือ Edge ในเครื่อง (ตั้ง `CHROME_PATH` ได้ถ้าอยู่ที่อื่น)
ถ้าล้มเหลวจะบันทึกภาพหน้าจอไว้ที่ `frontend/smoke.png`

## Deploy — Render (ฟรี ไม่ต้องใช้บัตร)

ไฟล์ [render.yaml](render.yaml) ตั้งค่าให้ครบแล้ว ใน Render เลือก **New → Blueprint**
ชี้มาที่ repo นี้ แล้วกรอกเฉพาะ 3 ค่าที่ระบบไม่ได้สร้างให้:

| ตัวแปร | ใส่อะไร |
|---|---|
| `DATABASE_URL` | connection string จาก [Neon](https://neon.tech) (ฟรีถาวร) |
| `SEED_ADMIN_PASSWORD` | รหัสผ่านผู้ดูแลที่ตั้งเอง |
| `HTTP_USER_AGENT` | `FloodWatchTH/1.0 (https://<ชื่อ>.onrender.com)` |

**ข้อจำกัดของแพลนฟรีที่ต้องรู้ 2 ข้อ**

1. **บริการหลับหลังไม่มีคนใช้ 15 นาที** ตื่นใช้เวลาราว 1 นาที
   แก้ได้ด้วย cron ฟรี (เช่น cron-job.org) ยิง `GET /api/health` ทุก 10 นาที
   ใช้เวลาราว 730 จาก 750 ชม./เดือนที่ได้ฟรี
2. **ไม่มีดิสก์ถาวร** รูปที่ผู้ใช้อัปโหลดจะหายทุกครั้งที่ deploy ใหม่
   ตัวรายงาน (ข้อความ ความลึก พิกัด) ไม่หาย หายเฉพาะรูป
   ถ้าต้องเก็บรูปถาวร ให้ย้ายไป object storage หรืออัปเป็นแพลนที่มีดิสก์

ตั้ง cron อีกตัวยิง `POST /api/stations/sync` ทุก ~15 นาที เพื่อให้ระดับน้ำสด

## Deploy (Railway)

```bash
railway init
railway add --database postgres     # ระบบจะใส่ DATABASE_URL ให้เอง
railway variables set JWT_SECRET=$(openssl rand -hex 32)
railway variables set SEED_ADMIN_PASSWORD='รหัสผ่านที่ตั้งเอง'
railway variables set SEED_DEMO_DATA=false
railway up
```

Dockerfile เป็นแบบ multi-stage service เดียว: Node build SPA → Python เสิร์ฟทั้ง API และไฟล์หน้าเว็บ
พอร์ตเดียว deploy ครั้งเดียว

แนะนำให้ mount volume ที่ `/data` เพื่อเก็บรูปที่ผู้ใช้อัปโหลด

ค่าตั้งทั้งหมดดูที่ [.env.example](.env.example) สิ่งที่**ต้อง**ตั้งก่อนใช้งานจริง:

| ตัวแปร | เหตุผล |
|---|---|
| `JWT_SECRET` | ค่าเริ่มต้นเป็นค่าสาธารณะ ใครก็ปลอม token ได้ |
| `SEED_ADMIN_PASSWORD` | ค่าเริ่มต้น `admin1234` อยู่ในซอร์สโค้ดนี้ |
| `SEED_DEMO_DATA=false` | กันข้อมูลสาธิตปนกับข้อมูลจริง |
| `HTTP_USER_AGENT` | นโยบาย Nominatim บังคับให้ระบุผู้ใช้งานจริง |
| `OSRM_BASE_URL` | เซิร์ฟเวอร์สาธิตสาธารณะมีลิมิต ไม่ใช่สำหรับ production |

## เพิ่มกล้อง CCTV ของจริง

ระบบมาพร้อมกล้อง **สาธิต** 8 ตัว (ตำแหน่งจริง แต่ภาพเป็นสตรีมทดสอบ ติดป้าย "สตรีมตัวอย่าง")
ผู้ดูแลเพิ่มกล้องจริงได้ที่ **หน้าผู้ดูแล → จัดการกล้อง**

รองรับ 5 รูปแบบ:

| ประเภท | ใช้กับ | หมายเหตุ |
|---|---|---|
| `snapshot` | ภาพนิ่ง `.jpg` ที่รีเฟรชเป็นรอบ | กล้องหน่วยงานไทยส่วนใหญ่เป็นแบบนี้ |
| `hls` | สตรีม `.m3u8` | เล่นด้วย hls.js |
| `mjpeg` | multipart stream | ผ่าน proxy เหมือน snapshot |
| `youtube` | YouTube Live | ใส่ลิงก์ปกติได้ ระบบแปลงเป็น embed ให้ |
| `iframe` | หน้าเว็บของผู้ให้บริการ | ฝังตรง |

**สำคัญ:** กล้องของหน่วยงานไทยมักไม่ส่ง CORS header และตรวจ `Referer` ทำให้เบราว์เซอร์
โหลดภาพตรง ๆ ไม่ได้ ระบบจึงดึงภาพผ่าน proxy ฝั่งเซิร์ฟเวอร์ที่
`GET /api/cameras/{id}/snapshot` พร้อมแคชสั้น ๆ — ให้ใส่ช่อง **"หน้าเว็บต้นทาง"**
เป็นหน้าดูกล้องของหน่วยงาน ระบบจะใช้เป็น `Referer` ให้อัตโนมัติ

> ก่อนดึงภาพจากกล้องของหน่วยงานใด ควรตรวจเงื่อนไขการใช้งานของหน่วยงานนั้น
> และขออนุญาตหากจำเป็น

## นำเข้าข้อมูลจากหน่วยงาน (เช่น รายงานเขตของ กทม.)

หน่วยงานมักประกาศจุดน้ำท่วมเป็นหน้าเว็บหรือไฟล์ ไม่ใช่ API ระบบจึงรับข้อมูล
ที่คุณมีสิทธิ์ใช้เข้ามาตรง ๆ ที่ **หน้าผู้ดูแล → นำเข้าข้อมูลหน่วยงาน**

**วางข้อความ** — คั่นแต่ละรายการด้วยบรรทัดว่าง:

```
21. ถ.วชิรธรรมสาธิต
ช่วงน้ำท่วม: บริเวณใกล้ ซ.วัดทุ่ง
ช่วง 3 แยกซอยวัดทุ่ง ท่วมสูง 20 ซม. หรือมากกว่า
เขตพระโขนง
https://maps.google.com/?q=13.686460,100.635200
```

ระบบอ่านให้อัตโนมัติ: ชื่อถนน, ช่วงที่ท่วม, เขต, ความลึก และ**พิกัด**

พิกัดรองรับทุกแบบที่พบจริง:
`13.686460, 100.635200` · `13°41'11.3"N 100°38'06.7"E` ·
`maps.google.com/?q=...` · `google.com/maps/@lat,lng,17z` · `...!3d...!4d...`

**อัปโหลดไฟล์** — `.csv` หรือ `.xlsx` ระบบจับคู่คอลัมน์ภาษาไทยให้เอง
(ถนน, ช่วง, เขต, ระดับน้ำ, พิกัด, สถานะ) และอ่านไฟล์ CSV ได้ทั้ง UTF-8 BOM, cp874 และ TIS-620

**ฟีด JSON** — `POST /api/import/feed` พร้อม `field_map` สำหรับกรณีที่หน่วยงาน
เปิด API ให้ใช้ในอนาคต เปลี่ยนแหล่งข้อมูลได้โดยไม่ต้องแก้โค้ด

ทุกช่องทางมีปุ่ม **"ทดลองอ่าน"** ดูผลก่อนบันทึกจริง รายการที่ไม่มีพิกัดจะถูกข้าม
พร้อมบอกเหตุผล และการนำเข้าซ้ำจะ**อัปเดต**รายการเดิม ไม่สร้างซ้ำ

## สถานีวัดระดับน้ำ (ข้อมูลจริง ใช้ได้ทันที)

ต่างจากกล้องและรายงานตรงที่ **ไม่ต้องตั้งค่าอะไรเลย** ระบบดึงเองตั้งแต่บูตครั้งแรก

ดึงจาก [คลังข้อมูลน้ำแห่งชาติ](https://www.thaiwater.net/) (`api-v3.thaiwater.net`)
805 สถานีทั่วประเทศ จาก สสน., กรมชลประทาน, กฟผ. และมูลนิธิอาสาเพื่อนพึ่ง (ภาฯ)
อัปเดตทุกประมาณ 10 นาที เก็บชื่อหน่วยงานเจ้าของข้อมูลไว้กับทุกสถานีเพื่อให้เครดิต

| อะไร | ที่ไหน |
|---|---|
| ซิงก์ตอนบูต | เปิด/ปิดด้วย `SYNC_STATIONS_ON_START` |
| ซิงก์ด้วยมือ / cron | `POST /api/stations/sync` (ต้องเป็นผู้ตรวจสอบขึ้นไป) |
| รายการสถานี | `GET /api/stations?overflowing_only=true` |
| สรุป | `GET /api/stations/summary` |

บนแผนที่แสดงเฉพาะสถานีที่**ล้นตลิ่ง** เพราะอีก ~700 สถานีที่ปกติเป็นแค่สัญญาณรบกวน
และในผลเช็คเส้นทางจะขึ้นเป็นบล็อกที่ 3 พร้อมระยะห่างจากเส้นทาง

> คลองล้นตลิ่ง **ไม่เท่ากับ** ถนนท่วม ระบบจึงแยกเป็นคนละชั้นข้อมูลและเขียนกำกับไว้ใน UI
> แต่คลองที่ล้นตลิ่งมักทำให้ถนนใกล้เคียงท่วมตามในเวลาไม่นาน จึงเป็นสัญญาณเตือนที่มีค่า

ข้อมูลที่เก่ากว่า `STATION_STALE_HOURS` (ค่าเริ่มต้น 6 ชม.) จะถูกทำให้จางและติดป้าย
"ข้อมูลไม่อัปเดต" แทนที่จะแสดงเป็นค่าปัจจุบัน

## กล้องที่ภาพค้าง

ปัญหาจริงที่เจอ: กล้องของ สำนักการระบายน้ำ กทม. (`dds.bangkok.go.th/cctv-image/cctvN.jpg`)
ยังตอบ HTTP 200 ปกติ แต่ `Last-Modified` ชี้ว่าภาพค้างมาเป็นเดือน

ระบบจึงอ่าน `Last-Modified` ของทุกภาพที่ดึงผ่าน proxy แล้วเก็บเป็น `last_frame_at`
กล้องที่ภาพเก่ากว่า `CAMERA_STALE_MINUTES` (ค่าเริ่มต้น 90 นาที) จะถูกตั้งสถานะเป็น
`stale` และ UI ขึ้นป้าย **"ภาพล่าสุด ... — ไม่ใช่ภาพสด"**

> การแสดงภาพเก่าเป็นภาพสดอันตรายกว่าไม่มีภาพเลย เพราะคนจะตัดสินใจขับจากภาพที่ไม่จริง

## กับดักของ MapLibre ที่ต้องรู้

maplibre-gl v6 ประมวลผล GeoJSON ทั้งหมดใน Web Worker และอ้างถึง worker ด้วย
`new URL('./maplibre-gl-worker.mjs', <url ของโมดูลตัวเอง>)` หลัง bundle พาธนั้นไม่มีอยู่จริง
ผลคือ **basemap ขึ้นปกติ แต่ทุกหมุดหายหมด และไม่มี error ให้เห็น** เพราะ raster tile
ไม่ต้องใช้ worker

แก้ไว้ 2 จุดใน [frontend/vite.config.js](frontend/vite.config.js) และ
[MapView.jsx](frontend/src/components/MapView.jsx):

| จุด | ทำอะไร |
|---|---|
| `optimizeDeps.exclude: ['maplibre-gl']` | กัน Vite pre-bundle ไปเขียนพาธ worker ผิด (เฉพาะ dev) |
| `worker: { format: 'es' }` | worker เป็น ES module และ import shared chunk ต่อ |
| `import ...?worker&url` + `setWorkerUrl()` | ให้ bundler emit worker แล้วบอก URL จริงกับ maplibre (ทั้ง dev และ production) |

**ถ้าอัปเกรด maplibre ต้องรัน `npm run smoke` กับทั้ง dev และ production build**
`optimizeDeps` แก้แค่ dev — production พังเงียบ ๆ ได้โดยที่ dev ปกติดี

และแผนที่จะรายงานข้อผิดพลาดของตัวเองขึ้นหน้าจอแล้ว แทนที่จะแสดงแผนที่ว่างเปล่าเฉย ๆ

## เส้นทางเลี่ยงน้ำท่วม

ค่าเริ่มต้นใช้ OSRM ซึ่งให้เส้นทางสำรองมาเปรียบเทียบ แต่ไม่สามารถสั่งให้ "หลบ" พื้นที่ได้

ถ้าตั้ง `ORS_API_KEY` (สมัครฟรีที่ openrouteservice.org) ระบบจะสร้างโซนห้ามผ่าน
รัศมี 120 ม. รอบทุกจุดที่ระดับ `deep` ขึ้นไป แล้วขอเส้นทางที่หลบโซนเหล่านั้นจริง ๆ
เพิ่มเป็นตัวเลือก **"เส้นทางเลี่ยงน้ำท่วม"**

เส้นทางเลี่ยงที่ยาวเกิน 2.5 เท่าของเส้นทางหลักจะถูกตัดทิ้ง — เลยจุดหนึ่ง
การรอน้ำลดคุ้มกว่าการขับอ้อมเพิ่มเป็นชั่วโมง

ถ้ายังไม่ได้ตั้งคีย์ ระบบยังทำงานปกติและ**บอกผู้ใช้ตรง ๆ** ว่าคำนวณเส้นทางเลี่ยงไม่ได้

## แชทบอท

ตอบจากข้อมูลในฐานข้อมูลด้วยกฎที่เขียนไว้ ไม่เรียก API ภายนอก เหตุผล:

- ตอนน้ำท่วมระบบต้องตอบได้โดยไม่พึ่งบริการภายนอกและไม่มีค่าใช้จ่ายต่อคำถาม
- ระดับน้ำเป็นข้อมูลความปลอดภัย การตอบจากข้อมูลที่ดึงมาจริงไม่สามารถ**แต่งชื่อถนน
  ที่ไม่ได้ท่วมขึ้นมาได้**

ตั้ง `CHAT_LLM_ENABLED=true` ได้ถ้าต้องการให้ Claude **เรียบเรียงคำตอบเดิม**ให้อ่านลื่นขึ้น
โดยห้ามเพิ่มข้อเท็จจริงใหม่ ถ้า API ล่มหรือเครดิตหมด ระบบใช้คำตอบจากกฎเหมือนเดิม

เข้าใจ 7 เจตนา: เช็คเส้นทาง A→B, เช็คจุดเดียว, เช็คใกล้ตัว, หากล้อง, ภาพรวม,
คำแนะนำความปลอดภัยตามความลึก, วิธีแจ้งเหตุ

จับชื่อสถานที่จาก 77 จังหวัด + 50 เขต กทม. + ชื่อจุดที่ผู้ใช้เคยแจ้ง + ชื่อกล้อง
ทนการพิมพ์ผิดได้ (เช่น "เชียงไหม่" → เชียงใหม่)

## สถาปัตยกรรม

```
backend/app/
├── main.py          FastAPI + เสิร์ฟ SPA
├── models.py        ตาราง + คำศัพท์ระดับน้ำ (enum เดียวใช้ทั้งระบบ)
├── routing.py       หัวใจ: วิเคราะห์เส้นทาง + โซนหลบน้ำท่วม
├── chatbot.py       เจตนาภาษาไทย + จับชื่อสถานที่
├── importers.py     แปลงรายงานหน่วยงานเป็นข้อมูลในระบบ
├── geocode.py       ชื่อสถานที่ → พิกัด (ข้อมูลในระบบก่อน แล้วค่อย Nominatim)
├── services.py      คะแนนความน่าเชื่อถือ, หมดอายุ, audit
└── routers/         auth, reports, cameras, route_check, chat, misc, admin, imports
```

**ตัดสินใจเชิงออกแบบที่ควรรู้**

- **ไม่ใช้ PostGIS** — ทุกคำค้นเชิงพื้นที่เป็น bounding box + คำนวณระยะทางในโค้ด
  Deploy บน Postgres ธรรมดาได้ทุกที่
- **รายงานหมดอายุใน 12 ชม.** — น้ำเคลื่อนที่ หมุดที่ข้อมูลไม่รองรับแล้วแย่กว่าไม่มีหมุด
  การกดยืนยันจะต่ออายุให้
- **คะแนนความน่าเชื่อถือ** — คำนวณจากแหล่งที่มา จำนวนคนยืนยัน และอายุของรายงาน
  รายงานเดี่ยวที่ยังไม่มีใครยืนยันและใกล้หมดอายุ จะไม่ทำให้ทั้งเส้นทางเป็นสีแดง
- **ช่วงความลึกเลือกค่าสูงสุด** — "15-20 ซม." อ่านเป็น 20 เพราะการรายงานต่ำกว่าจริง
  คือความผิดพลาดที่ทำให้รถจม

## ความปลอดภัย

- Popup บนแผนที่สร้างด้วย DOM + `textContent` ไม่ใช่ HTML string — ชื่อสถานที่
  มาจากผู้ใช้ทั่วไป จึงต้องไม่ถูกตีความเป็น markup
- รูปเป็น same-origin `/uploads/` เท่านั้น
- รูปที่อัปโหลดถูก decode และ encode ใหม่ด้วย Pillow — ตรวจว่าเป็นรูปจริง,
  ลบ EXIF (รวมพิกัด GPS ของกล้อง), จำกัดขนาด
- rate limit แยกตาม IP/ผู้ใช้ สำหรับแจ้งเหตุ, แชท, ล็อกอิน, อัปโหลด, ตรวจเส้นทาง
- ล็อกอินจำกัดทั้งราย IP และรายชื่อผู้ใช้ที่ถูกลองรหัส
- ป้องกันการลดสิทธิ์จนไม่เหลือผู้ดูแลระบบที่ใช้งานได้
- ไม่ส่ง stack trace ออกไปที่เบราว์เซอร์

**ยังไม่ได้ทำ** (ควรทำก่อนเปิดใช้จริงวงกว้าง): ยืนยันอีเมล, ลืมรหัสผ่าน,
ตรวจ abuse เชิงลึก และ rate limit แบบกระจาย (ตอนนี้นับในโปรเซสเดียว —
ถ้าสเกลเป็นหลาย replica ต้องย้ายไป Redis)

## หมายเหตุเรื่องข้อมูล

- พิกัดกลางจังหวัดเป็น**ค่าประมาณ** (ใช้ตัวเมือง ไม่ใช่ centroid ของขอบเขตจริง)
  ใช้สำหรับจัดกลุ่มและจับชื่อสถานที่ ไม่ใช่สำหรับวาดขอบเขต
- ชื่อเขตกรุงเทพฯ 50 เขตใส่ไว้เพื่อให้แชทบอทจับชื่อได้ตั้งแต่วันแรก
  ควรตรวจทานการสะกดกับข้อมูลราชการก่อนใช้งานจริง ผู้ดูแลเพิ่ม/แก้พื้นที่ได้ผ่าน API
- `create_all` สร้างตารางให้ตอนบูต เหมาะกับ schema ปัจจุบัน
  ถ้าต้องแก้ schema โดยรักษาข้อมูลเดิม ให้เพิ่ม Alembic
